# 社内イントラネット設計ドキュメント

## 1. 目的・背景

全社員が日常的に利用する情報ポータルとして、社内イントラネットを構築する。
初期スコープは以下の2機能とする。

- **お知らせ・掲示板**：全社/部署からの通知を一覧・重要度別に確認できる
- **ドキュメント・ナレッジ共有**：社内規程・マニュアル・FAQ等を検索・閲覧できる

本リポジトリは `a11y`（アクセシビリティ）を第一級の関心事とする方針のため、
本設計もWCAG 2.1 AA準拠を前提とする（詳細は「6. アクセシビリティ要件」）。

## 2. 対象ユーザー

| ユーザー | 主な利用シーン |
|---|---|
| 一般社員 | お知らせの確認、規程・マニュアルの検索 |
| 投稿者（総務・人事・各部署担当者） | お知らせの作成・編集・公開 |
| ドキュメント管理者 | ナレッジ記事の作成・分類・公開/非公開管理 |
| 管理者 | ユーザー・権限・カテゴリ管理 |

## 3. 全体構成（サイトマップ）

```
/                      トップページ（お知らせ最新一覧 + よく見られる記事）
├── /announcements      お知らせ一覧
│   ├── /announcements/:id      お知らせ詳細
│   └── /announcements/new      お知らせ投稿（権限者のみ）
├── /docs                ドキュメント・ナレッジ
│   ├── /docs/search         検索結果
│   ├── /docs/:category      カテゴリ別一覧
│   └── /docs/:category/:id  記事詳細
├── /search              全文横断検索（お知らせ＋ドキュメント）
└── /admin               管理画面（カテゴリ・権限・投稿者管理）
```

## 4. 機能設計

### 4.1 お知らせ・掲示板

- 一覧はカード/テーブル表示を切替可能。デフォルトはカード表示
- 属性：タイトル、本文（リッチテキスト）、発信部署、重要度（緊急/重要/通常）、
  公開期間（開始日〜終了日）、既読/未読、添付ファイル
- 重要度「緊急」は一覧上部に固定表示し、視覚的な色分けだけでなくラベルテキストでも区別する
  （色のみに依存しない：WCAG 1.4.1 対応）
- 未読/既読の管理はユーザー単位。未読件数をヘッダーにバッジ表示
- 公開期間終了後は自動的に一覧から除外（アーカイブには残す）
- 投稿権限：役割ベース（RBAC）。投稿者ロールを持つユーザーのみ `/announcements/new` にアクセス可

### 4.2 ドキュメント・ナレッジ共有

- カテゴリ階層（例：人事規程／経理規程／ITマニュアル／FAQ）とタグの併用
- 全文検索（タイトル・本文・タグを対象）。検索窓はヘッダーに常時表示
- 記事にはバージョン情報（最終更新日・更新者）を明示し、古い情報の誤認を防ぐ
- 添付ファイル（PDF/Office文書）のダウンロードとインライン変換表示（可能な範囲で）
- 公開範囲設定：全社公開／部署限定／管理者のみ

### 4.3 共通

- グローバルヘッダー：ロゴ、全文検索、通知（未読お知らせ）、ユーザーメニュー
- グローバルナビゲーション：お知らせ／ドキュメント／検索
- パンくずリストで現在位置を常に明示

## 5. 情報アーキテクチャ・データモデル（概略）

```
User        { id, name, department, roles[] }
Announcement { id, title, body, department, priority, publishFrom, publishTo,
               attachments[], authorId, createdAt, updatedAt }
ReadStatus  { userId, announcementId, readAt }
Category    { id, name, parentId }
Article     { id, title, body, categoryId, tags[], visibility,
              authorId, updatedBy, createdAt, updatedAt, attachments[] }
```

- 権限はロールベース（一般社員／投稿者／ドキュメント管理者／管理者）
- お知らせ・記事とも論理削除（非表示化）を基本とし、物理削除は管理者のみ

## 6. アクセシビリティ要件

CLAUDE.md の方針に準拠し、以下を満たすこと。

- すべての操作をキーボードのみで完結できること（フォーカス順序が視覚順と一致）
- ランドマーク要素（`<header>` `<nav>` `<main>` `<footer>`）でページ構造を明示
- 画像には意味のある `alt`（装飾画像は `alt=""`）
- コントラスト比：通常テキスト4.5:1以上、大テキスト3:1以上
- 重要度・状態表示は色以外の手段（アイコン＋テキストラベル）でも判別可能にする
- モーダル（お知らせ詳細のプレビュー等）はフォーカストラップを実装し、閉じたら元の要素へフォーカスを戻す
- フォーム（投稿画面）は `<label>` と入力欄を明示的に関連付け、エラーはテキストで通知
- 自動化チェックを `axe-core` 等でCIに組み込む（実装フェーズで検討）

## 7. 非機能要件（初期方針）

- レスポンシブ対応（PC/タブレット優先、モバイルは閲覧を想定）
- 検索は入力から結果表示まで体感1秒以内を目標
- 添付ファイルはウイルススキャン済みのもののみ配信（インフラ側で担保）

## 8. 未確定事項（要確認）

以下は本ドキュメントでは決定せず、実装着手前に確認する。

- 技術スタック（フロントエンド／バックエンド／認証基盤：SSO有無など）
- ホスティング環境（社内オンプレ／クラウド）
- 認証方式（社内AD連携の要否）
- 既存システム（人事DB等）との連携要否
